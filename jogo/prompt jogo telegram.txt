1. VISÃO DO JOGO & UNIVERSO
1.1 Conceito Central

"No coração do Vazio Digital, Guardiões ancestrais dormem em cristais de energia. Quem os despertar e cultivar sua força poderá extrair o próprio tecido da realidade — e convertê-lo em riqueza real."

CryptoRealm: Guardians of the Void é um jogo Idle Play-to-Earn ambientado em um universo de fantasia cibernética, onde os jogadores recrutam e evoluem Guardiões — entidades místico-digitais que extraem Void Energy (VE), a moeda premium sacável, e Crystal Shards (CS), o recurso off-chain de progressão.
1.2 Pilares do Design
PilarDescriçãoAcessibilidadeZero conhecimento de crypto necessário para começarRetenção VicianteLoops de progressão curtos (minutos) e longos (semanas) simultâneosGanho RealSaques reais em TON criam motivação tangível e word-of-mouth orgânicoCrescimento ViralSistema de referências integrado ao DNA do TelegramFairness PercebidaPay-to-win suavizado por mecanismos de catch-up para free players
1.3 Proposta de Valor Única (UVP)
Diferente de outros idle games P2E, CryptoRealm elimina a complexidade de wallets no onboarding — o jogador começa a ganhar em 30 segundos sem precisar conectar carteira. A wallet TON só é obrigatória no momento do primeiro saque real.

3. MECÂNICAS CORE LOOP
3.1 Loop Primário (Minutos)
COLETAR recursos acumulados
    → USAR Crystal Shards para fazer upgrade
    → GUARDIÕES mais poderosos mineram mais rápido
    → Volta para COLETAR
3.2 Loop Secundário (Horas)
ACUMULAR Void Energy passivamente
    → DECIDIR: sacar VE ou reinvestir em novos Guardiões
    → NOVOS Guardiões aumentam a taxa total
    → Aumenta a pressão de convidar amigos para acelerar
3.3 Loop Terciário (Dias/Semanas)
MISSÕES DIÁRIAS completadas
    → BÔNUS de multiplicador temporário
    → RANKING semanal de top farmers
    → RECOMPENSAS especiais para top 50
    → Guardiões Lendários Sazonais (edição limitada)

5.2 Notas de Balanceamento

ROI mais longo para Lendários é intencional: cria pressão de burn e desincentiva compra única de personagens caros como "investimento puro"
O ROI base (sem upgrades) deve ficar entre 45–80 dias para toda a tabela
Upgrades e ferramentas reduzem o ROI, criando incentivo de progressão
Revisão obrigatória a cada 30 dias com base no preço real do VE no mercado

Conta indicada deve fazer depósito mínimo (0.5 TON) para ativar comissão
Máximo de 500 referências ativas por conta (evita farms de contas falsas)
IP + Device fingerprint para detectar auto-referências
Cooldown de 7 dias entre referência e ativação de comissão

8.2 Modelo de Farming Off-Chain
O farming acontece inteiramente no PostgreSQL, com ticks calculados pelo backend. Nenhuma transação blockchain é gerada durante o farming.
typescript// Pseudocódigo do Farming Engine
async function processFarmingTick(userId: string) {
  const player = await db.player.findUnique({ userId });
  const guardians = await db.guardian.findMany({ userId, active: true });
  
  const totalVEPerHour = guardians.reduce((sum, g) => {
    const basePower = RARITY_POWER[g.rarity];
    const levelMultiplier = 1 + (g.level - 1) * 0.20;
    const toolMultiplier = await getToolMultiplier(userId);
    return sum + (basePower * levelMultiplier * toolMultiplier);
  }, 0);
  
  const hoursSinceLastCollect = getHoursDiff(player.lastCollectAt, now());
  const cappedHours = Math.min(hoursSinceLastCollect, 48); // cap de 48h
  
  const earnedVE = totalVEPerHour * cappedHours;
  const earnedCS = (totalVEPerHour * 150) * cappedHours; // ratio CS:VE = 150:1
  
  await db.player.update({
    userId,
    pendingVE: { increment: earnedVE },
    pendingCS: { increment: earnedCS },
    lastCollectAt: now()
  });
}
8.3 Fluxo de Saque (Withdraw Flow)
Jogador → Solicita Saque
     ↓
Backend valida:
  • Saldo suficiente
  • KYC básico (wallet conectada)
  • Limite diário não atingido
  • Conta não banida/sinalizada
     ↓
Cria registro na tabela `withdrawals` (status: PENDING)
     ↓
Admin vê na fila → Revisa → Clica APROVAR
     ↓
Backend chama Smart Contract na TON:
  treasury_wallet.transfer(player_wallet, amount_after_fee)
     ↓
Aguarda confirmação on-chain (webhook TON Center)
     ↓
Atualiza status: APPROVED → COMPLETED
     ↓
Notificação via Telegram Bot para o jogador
8.4 Smart Contract — Funções Principais (FunC)
Treasury Contract:
  ├── transfer(to: Address, amount: Coins) — apenas callable pelo backend key
  ├── deposit() — recebe TON de compras de Guardiões
  ├── burn(amount: Coins) — destrói VE de taxas
  ├── getBalance() — consulta saldo atual
  └── setAdminKey(newKey: PubKey) — atualiza chave admin (multi-sig obrigatório)

10. ANTI-FRAUDE & SEGURANÇA
10.1 Camadas de Proteção
Camada 1 — Frontend:

Verificação de assinatura initData do Telegram em 100% das requisições
Rate limiting por Telegram ID (não por IP, que pode ser compartilhado)
Obfuscação de código do TMA

Camada 2 — API:

JWT com expiração curta (15 minutos) + refresh token
Rate limiting granular por endpoint (ex: coleta: máx 10/min)
Validação server-side de todos os cálculos de farming (nunca confiar no cliente)
Idempotency keys em todas as operações financeiras

Camada 3 — Banco de Dados:

Todas as operações de saldo em transactions ACID com locks
Trigger de auditoria automático em tabelas financeiras
Row-level security no PostgreSQL
Backup automatizado a cada 6h + replicação em região diferente

Camada 4 — Blockchain:

Smart contract auditado por terceiros antes do lançamento
Multi-sig para alterações críticas no contrato
Whitelisting de endereço do backend no contrato
Limite diário de saques programado no próprio smart contract

10.2 Risk Score Algorithm
Risk Score (0–100) = Σ dos seguintes fatores:

+ 30 pts: Criação de conta + saque em < 48h
+ 25 pts: Mesmo device/IP com outra conta banida
+ 20 pts: Padrão de coleta com timing robótico (< 0.5s de variação em 50+ coletas)
+ 15 pts: Farming rate > 3x média da raridade dos Guardiões
+ 10 pts: 3+ contas no mesmo IP (sem VPN detectado)
+ 10 pts: Referência para conta no mesmo IP

Score > 60: Saque bloqueado automaticamente, revisão manual obrigatória
Score > 80: Conta suspensa automaticamente, notificação ao admin
